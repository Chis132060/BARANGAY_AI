feat(ai): Implement Production GraphQL API, QA/QC Framework, and Embedding Fallbacks

This massive architectural release completely separates the core AI Brain logic from the transport layer by establishing a secure, production-grade Strawberry GraphQL API on top of FastAPI. Furthermore, it incorporates strict embedding space isolation to completely eliminate vector dimension mismatch issues, and establishes the full ISO-aligned Quality Assurance (QA) and Quality Control (QC) frameworks.

### Presentation Layer (GraphQL & FastAPI)
We have introduced a dedicated `apps/api/graphql` directory which houses the entire Strawberry GraphQL implementation. The `schema.py` establishes the core `Query`, `Mutation`, and `Subscription` types, ensuring that the frontend interacts with a strictly typed API rather than raw backend services. To enforce security, `security.py` introduces JWT context extraction and handles query depth protections to prevent complex recursive query attacks. Furthermore, `types.py` guarantees the exact JSON structures for sources and responses, while `errors.py` normalizes all failure states (such as `AI_UNAVAILABLE` or `RATE_LIMITED`) so that internal stack traces or API keys are never leaked to the client.

### Real-Time Streaming Layer
To support dynamic, snappy user interfaces, we introduced `apps/api/services/stream_service.py`. This service handles the explicit `AIStreamEvent` lifecycle over WebSockets (via GraphQL Subscriptions). It correctly emits `STARTED`, `TOKEN`, `SOURCE`, `PROVIDER_FALLBACK`, `COMPLETED`, and `ERROR` events. Most importantly, it implements a "Buffer-Then-Validate" strategy: tokens are streamed instantly to the user for low latency, but the system internally buffers the entire response text. Only after the text undergoes rigorous hallucination and source grounding checks via the `ResponseValidator` does the stream yield its final `COMPLETED(grounded=True/False)` event. This ensures the frontend never mistakenly trusts unvalidated AI generation.

### Persistent Session Memory Layer
We have entirely removed the volatile in-memory dictionary from `memory_service.py`. Conversation history is now permanently backed by PostgreSQL via the new `20260816000004_graphql_sessions.sql` migration. This migration creates the `ai_sessions` and `ai_messages` tables. To prevent double-posting from mobile application network drops, we implemented strict message idempotency using a unique `client_request_id` constraint on the `ai_messages` table. The data is secured using Row Level Security (RLS) policies, guaranteeing that users can only fetch or modify sessions they own.

### Embedding and Ingestion Layer
The AI knowledge ingestion pipeline has been hardened to gracefully handle `429 Quota Exceeded` errors without losing chunks. We established `apps/api/services/ai/embeddings/manager.py` and `queue.py` to route embedding requests to completely isolated vector spaces. The migration `20260816000003_embedding_spaces.sql` provisions separate tables (`knowledge_embeddings_gemini` and `knowledge_embeddings_local`) specifically typed for their dimensions (`vector(3072)` and `vector(384)`). This mathematically prevents cross-model retrieval poisoning.

### Quality Assurance and ISO Compliance Layer
Finally, we have massively expanded the `docs/compliance/` directory with 24 distinct architectural documents detailing our alignment with ISO 27001, 42001, and 23894. This includes `graphql-security.md`, `qa-policy.md`, and `incident-management.md`. We also created the foundational test scaffold directories (`tests/graphql/` and `tests/ai/`), laying the groundwork for exhaustive End-to-End, Load, and Chaos testing required by our strict Quality Gates before any production deployment.
